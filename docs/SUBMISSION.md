# Конкурсная сдача

Требования сверены с регламентом 12.11.2026; актуальная ссылка — в `SOURCES.md`.

## Автоматическая оценка

- ZIP до 128 МБ; `solution.py`, `requirements.txt` и необходимые `.py` лежат непосредственно в корне. Вложенные пакеты с необходимым для исполнения кодом запрещены регламентом.
- Платформа предоставляет `questions.csv` и `knowledge-base.zip` в `DATA_DIR` (по умолчанию `data`). Их не нужно класть в ZIP.
- Вопросы: UTF-8 CSV с колонками `id,question`. Каждый ID — независимый тест. Историю внутри вопроса надо учитывать до последней реплики пользователя; её фактическое представление сверить по demo-файлам.
- Результат: `submission.csv` в текущем рабочем каталоге, UTF-8, ровно `id,answer`. Каждый ID один раз; ответ непустой, максимум 10 000 символов. Использовать стандартный CSV writer для кавычек, запятых и переводов строки.
- Генеративная модель — Qwen3.8-27B через OpenAI-совместимый прокси. Имя модели и доступ берутся из окружения, а не из константы в коде.
- Учитывать альтернативные имена `LLM_*` / `OPENAI_*`, `BASE_URL` и `GEN_MODEL`; адрес запроса генерации — `{base_url}/chat/completions`. Не добавлять `/v1` автоматически без проверки предоставленного base URL.
- `TEMPERATURE`, `MAX_TOKENS`, `MAX_WORKERS` и настройки retrieval читаются из среды с разумными локальными значениями по умолчанию.
- Доступны BAAI/bge-m3 и необязательный Qwen3 Reranker 8B через тот же прокси. Формат запросов эмбеддингов/реранкера уточнить по фактической документации/примеру до реализации.
- 8 CPU, 16 ГБ RAM, 20 минут на весь запуск. Ограниченные повторы 429/5xx/тайм-аутов; без бесконечных циклов. 401 сообщается как ошибка доступа.
- Нельзя выполнять `pip install` из скрипта. Зависимости — только из разрешённого списка, версии закреплены.
- 5 сабмитов в день на команду, сброс в 00:00 МСК; загрузку выполняет Платон.

## Как не разойтись с веб-версией

Веб и CSV используют модули пакета `energytool/`: `consultant.py`, `llm_client.py`, `retrieval.py`, `chunking.py`, `kb_loader.py`, `contracts.py`. Внутри этих модулей не импортировать `backend` и `frontend` и не читать пользовательскую SQLite для ответа конкурсному ID.

Для каждого теста отдельный контекст; модель и неизменяемый индекс можно переиспользовать. Порядок строк результата должен совпадать со входом для удобства проверки. При сбое отдельного обращения записать осторожный запасной ответ и завершить процесс успешно, если полный CSV создан: иначе платформа отклонит весь сабмит, не оценивая остальные строки. Число таких ответов печатается отдельно; это не качественная генерация. Если входные файлы отсутствуют или CSV не удалось создать, процесс завершается с ошибкой.

`scripts/build_submission.py` преобразует импорты пакета `energytool/` и собирает плоские модули и минимальный закреплённый `requirements.txt` в `runtime/submission.zip`, проверяет синтаксис и структуру ZIP. Упаковка сама по себе не доказывает качество ответов. `solution.py` проходит локальный прогон через явно синтетический прокси; работа с реальным прокси организаторов должна быть отдельно подтверждена перед отправкой. Конкурсный сабмит выполняет Платон, архив автоматически не загружается.

## Финальный прототип

Нужны исходники, README, Dockerfile, `compose.yaml`, `.dockerignore`, закреплённые зависимости, `.env.example` без секретов и PDF-презентация. В README — одна команда старта всех компонентов, порты, конфигурация, проверка основного сценария и реальные ограничения.

Вариант сдачи: PDF с репозиторием на первом слайде либо ZIP с кодом, документацией и PDF. Приватному репозиторию по условиям кейса требуется доступ аккаунта жюри `hack-and-change-2026`; изменение доступа выполняет владелец при финальной сдаче. Закрытые исходные материалы не становятся частью открытого репозитория.
