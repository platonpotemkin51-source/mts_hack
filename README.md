# МТС Energytool — ИИ-консультант

Русскоязычный прототип: посетитель описывает задачу, получает ответ на основе предоставленной базы знаний, видит карточку задачи и может сохранить заявку с резюме для менеджера. Архив хранит все сессии, включая разговоры без заявки. Реальной отправки в CRM или почту нет.

## Быстрый запуск

Нужны Docker Desktop с запущенным Linux Engine и доступ к OpenAI-совместимому прокси. Закрытую базу организаторов положите в `data/knowledge-base.zip`. Скопируйте `.env.example` в `.env` и заполните `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`. Не добавляйте `.env` или базу в Git.

```powershell
Copy-Item .env.example .env
docker compose up --build
```

Откройте [интерфейс](http://localhost:5173), [health](http://localhost:8000/api/health) или [API-документацию](http://localhost:8000/docs). `GET /api/ready` возвращает 200 лишь при доступной базе и заполненных настройках модели; без них — 503. Наличие настроек ещё не доказывает доступность прокси. При первом запуске индекс BM25 строится из базы; далее объект поиска переиспользуется. `runtime/` монтируется в контейнер и сохраняет SQLite и кэш после перезапуска.

Для локальной разработки без Docker используйте Python 3.11 и Node.js 22+:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --env-file .env --port 8000
```

В другом терминале: `cd frontend`, `npm ci`, `npm run dev`. По умолчанию UI обращается к настоящему API. `VITE_USE_MOCK_API=true` включает явно помеченный синтетический mock только для демонстрации интерфейса.

## Как устроено решение

| Часть | Назначение |
| --- | --- |
| `kb_loader.py`, `chunking.py`, `retrieval.py` | Безопасное чтение ZIP, смысловые фрагменты, BM25, необязательные embeddings и гибрид RRF |
| `consultant.py` | Единое ядро веба и конкурсного CSV: контекст, поиск, ограничения, ответ и карточка |
| `llm_client.py` | OpenAI-совместимый прокси, тайм-ауты и ограниченные повторы |
| `backend/` | FastAPI, SQLite, сессии, заявки, идемпотентные сообщения |
| `frontend/` | Vue-чат, карточка, архив, заявка, отладка и мобильный интерфейс |
| `solution.py` | Независимая обработка каждого CSV-ID, вывод `submission.csv` |

Продуктовые факты и ограничения передаются модели только из найденных фрагментов. Пользовательские параметры берутся из диалога; найденные тексты и реплики считаются недоверенными данными. Если модель не указала реально переданный ID источника, ядро даёт осторожный ответ без рекомендации. Это защита от части ошибок, но не формальная проверка истинности текста модели. Вопросы пошаговой настройки приборов вне задачи консультанта.

### Настройки

`LLM_BASE_URL` или `OPENAI_BASE_URL` — адрес прокси, без автоматического `/v1`; `LLM_API_KEY` или `OPENAI_API_KEY` — служебный ключ; `LLM_MODEL`, `OPENAI_MODEL` или `GEN_MODEL` — имя модели. Конкурсная платформа предоставляет их сама. Для генерации используется `{base_url}/chat/completions`; для embeddings — `{base_url}/embeddings`. `TEMPERATURE`, `MAX_TOKENS`, `MAX_WORKERS`, `TOP_K`, `DATA_DIR`, `CACHE_DIR`, `SQLITE_PATH` читаются из среды. `RETRIEVAL_MODE=bm25` работает без embeddings; `embeddings` и `hybrid` требуют доступа к прокси и пока не подтверждены на реальном сервисе. `SESSION_IDLE_MINUTES` закрывает потерянные активные сессии (по умолчанию 60 минут), сохраняя их в архиве.

### Безопасный повтор и закрытие

Браузер отправляет случайный `request_id` вместе с сообщением. После неопределённой ошибки кнопка повторной проверки использует тот же ID; сервер возвращает ранее записанный ответ либо продолжает неуспешный запрос без второго пользовательского сообщения. Новый диалог и закрытие страницы отправляют запрос закрытия по `request_id`, если ответ ещё не получен. Если браузер не доставил его, сервер закрывает бездействующую сессию по сроку. Архив остаётся доступным только для чтения. Создание заявки требует явного согласия и тестовых контактов; повтор в одной сессии даёт 409.

## Конкурсный CSV

Положите закрытые `questions.csv` и `knowledge-base.zip` в `DATA_DIR` (по умолчанию `data`). При настроенном прокси:

```powershell
.\.venv\Scripts\python.exe solution.py
.\.venv\Scripts\python.exe scripts/build_submission.py
```

`solution.py` создаёт в текущем каталоге UTF-8 `submission.csv` с ровно `id,answer`, сохраняет порядок и обрабатывает историю внутри вопроса. Для отдельного ID не используется состояние предыдущего. Архив `runtime/submission.zip` содержит только плоские исходные Python-файлы и закреплённые зависимости; входные данные в него не входят. **Конкурсный сабмит автоматически не отправляется.** Ошибка модели отмечается ненулевым кодом выхода; заполненный осторожным сообщением CSV не считается успешной генерацией.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s evaluation/rag -p 'test_*.py'
.\.venv\Scripts\python.exe -m unittest discover -s evaluation/backend -p 'test_*.py'
cd frontend
npm run build
npm test
```

В `evaluation/backend/fake_proxy.py` есть **синтетический тестовый прокси**. Он проверяет транспорт и сквозное подключение через настоящий backend и RAG, но не качество генеративной модели. Основной сценарий и ограничения описаны в [демо](docs/DEMO.md), статус проверок — в `evaluation/`. Финальная [PDF-презентация](docs/energytool-presentation.pdf) содержит только синтетические визуальные материалы.

## Известные ограничения

- Без локального доступа к прокси организаторов реальные ответы Qwen3.8-27B, embeddings и полный конкурсный прогон на нём не подтверждены. Тестовый прокси не заменяет эту проверку.
- Качество BM25 по 18 демовопросам измерено только по времени; автоматической разметки ответов нет. Гибрид стоит выбирать после отдельной оценки качества.
- Прототип не имеет авторизации пользователей: архив доступен всем, кто имеет доступ к локальному серверу. Для публичного развёртывания нужна аутентификация и политика хранения персональных данных.
- Не храните в Git исходную базу, вопросы, CSV-ответы, индексы, SQLite, переписки и секреты. Используйте только вымышленные контакты.
