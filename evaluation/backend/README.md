# Интеграционные проверки backend и конкурсного адаптера

Состояние 15.11.2026. Команды из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s evaluation/backend -p 'test_*.py'
.\.venv\Scripts\python.exe -m unittest discover -s evaluation/rag -p 'test_*.py'
cd frontend
npm run build
npm test
```

27 backend/CSV-тестов и 41 RAG-тест прошли. Используются вымышленные документы и ответы локального стаб-моделя. Проверены: источники, пустой поиск, смена объекта, история CSV, отказ от контактов, технический вопрос вне задачи, повторы 503/401, изоляция сессий, сохранность после перезапуска, согласие и дубликат заявки, отмена потерянного запроса, запрет обгона и запоздалого повтора. Из 13 UI-сценариев все прошли после интеграции; проверка сборки TypeScript/Vite тоже прошла.

С реальной закрытой базой локально построен BM25 и выполнены 18 демовопросов: построение индекса около 102 мс, медиана поиска 0,147 мс, p95 0,339 мс. Разметки этих вопросов нет, поэтому hit-rate и качество рекомендаций не заявляются.

Docker Compose собрал оба сервиса. С `evaluation/backend/fake_proxy.py` (явно **синтетический** прокси) браузер прошёл через настоящий nginx, FastAPI, SQLite и BM25 по настоящей базе: ответ со ссылкой на источник и временем, исправление карточки, заявка, архив и мобильная ширина. После перезапуска backend архив сохранился. `solution.py` и распакованный плоский ZIP создали 18 уникальных, непустых CSV-строк с корректным форматом через тот же синтетический прокси.

**Не подтверждено:** качество ответов и стабильность настоящего Qwen3.8-27B через прокси организаторов, работа embeddings/hybrid на нём, полный конкурсный тайминг с реальной моделью, оценка на скрытых тестах. Тестовый прокси не заменяет проверку реальной модели. Сабмит на платформу не отправлялся.

После независимого аудита исправлены гонки ответов и запоздалых повторов, а также риск старта CSV-вопроса перед исчерпанием 20 минут. Виртуальный тест проверяет, что новые вопросы прекращают запускаться с 90-секундным запасом для завершения и записи CSV. Это контроль времени на известной конфигурации; фактический полный прогон на прокси организаторов ещё нужен.

После ответа поддержки платформы устранена причина отклонения загруженного архива: раньше один запасной ответ приводил к коду выхода 1 уже после записи submission.csv. Новый распакованный ZIP в отдельном каталоге завершился с кодом 0 и записал все 18 строк как при 18 намеренных сбоях модели, так и при 18 успешных ответах синтетического прокси. Для конкурсного вызова увеличены доступный бюджет токенов и время ожидания одной попытки по образцу организаторов. Реальная модель по-прежнему не проверена локально.

Следующий эксперимент и раздельные метрики генерации и поиска описаны в ../quality/README.md. Уточнения без продуктовых фактов теперь сохраняются без источника, неизвестные ссылки не дают права на утверждение, а конкурсный режим переносит ошибку вспомогательной карточки без потери ответа.
