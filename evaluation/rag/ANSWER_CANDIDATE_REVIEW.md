# Ревью 8682b26 после результата 46,513

Проверен origin/feature/answer-quality, коммит 8682b26. Пользователь показал
46,513 для submission-answer-quality-8682b26-hybrid-chunks.zip; контроль —
61,664. Наблюдаемая разница −15,151 балла. Сам отправленный ZIP и результаты
по отдельным вопросам локально отсутствуют. Причины всей разницы не установлены.

## Воспроизведённые проблемы

Все примеры ниже синтетические. Генератор возвращает один и тот же правильный
ответ как при первом запросе, так и при repair. В источнике достаточно сведений.
Контрольный consultant.py из 40e8ef7 сохраняет четыре ответа за один вызов;
8682b26 делает два вызова и во всех четырёх случаях заменяет ответ ограничением
«В предоставленной базе не нашлось достаточных подтверждений…».

| Приоритет | Место consultant.py в 8682b26 | Ошибка |
| --- | --- | --- |
| P1 | 433–438 | Нумерация списка `1. … 2. …` считается новыми фактами. Также точный перевод `750 кВт` в `0,75 МВт` отклоняется проверкой сырых чисел раньше проверки нормализованных величин. |
| P1 | 399–405 | Ответ «Количество приборов уже известно. Как сейчас собираются показания?» считается повторным вопросом о количестве, если клиент уже назвал 12 приборов. Фильтр соединяет вопросительный знак одного предложения с упоминанием количества в другом. |
| P2 | 443–445 | Фраза «Производитель гарантирует сохранность архива макета» отклоняется даже при дословном подтверждении в процитированном источнике. Наличие слова «гарантирует» само по себе трактуется как неподтверждённое обещание. |

Ошибки стали обязательными для конкурсного режима: 638–641 не учитывают
ANSWER_REVIEW=0; результат repair снова проходит тот же фильтр на 651–652;
неудача на 662–667 удаляет полезный ответ и источники. Исправлять нужно ложные
срабатывания и проверять сохранение полностью подтверждённых ответов, включая
списки и эквивалентные единицы. Отключение всей защиты от выдуманных чисел
не является предлагаемым исправлением.

## Изоляция эксперимента

e22d9c2 включил dev/Artem b23253e в ветку коллеги. Её retrieval.py побайтно
совпадает с нашим V3, а не с архивом 61,664. Помимо генерации изменены добор
условий, связи продуктов и словарь поиска. Включение реранкера управляется
отдельным флагом; по имени ZIP нельзя установить фактическое значение флага.
Поэтому данный результат не является изолированным сравнением генерации.

Для финала не объединять две неудачные ветки целиком. Сохранённый контрольный
submission-hybrid-evidence.zip остаётся лучшим наблюдаемым результатом.
Любой новый кандидат следует собирать с его поиском и только явно выбранными
изменениями генерации. Это рекомендация по контролю эксперимента, не обещание
повышения скрытой метрики.

## Как повторить

```sh
python3 evaluation/rag/review_answer_candidate.py
```

Скрипт загружает оба зафиксированных consultant.py через git show, работает на
вымышленных материалах, не обращается к API. Завершение с кодом 0 означает, что
четыре описанные регрессии старого коммита воспроизведены, а не что он исправен.
Полные диагностические результаты пишутся в игнорируемый runtime/evaluation/.

Также в отдельном снимке 8682b26 прошли 113 backend/CSV и 80 RAG-тестов.
Это показывает пробел в существующих проверках: они не гарантируют сохранение
правильного ответа. Реальный Qwen и повторная оценка судьи не запускались.
