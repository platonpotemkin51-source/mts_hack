# Проверка качества через Groq, 15 ноября 2026

Исторический отчёт для `d3a71f2`. Последующие изменения описаны в
[SCORE_SPRINT.md](SCORE_SPRINT.md); текущая конкурсная схема и значения флагов
отличаются от приведённых ниже.

Это кандидат для следующей проверки Qwen, а не подтверждённый рост конкурсного
score. Контроль — `c00f658`. Генератор — Groq `openai/gpt-oss-120b`, temperature 0,
2048 выходных токенов. История экспериментов и границы отбора — в
[GROQ_PLAN.md](GROQ_PLAN.md).

## Что изменилось

- Модель получает отдельные дословные сведения клиента: объект, число приборов,
  модель и способ сбора, когда они явно названы. Последнее исправление важнее
  старого числа; реплики ассистента, гипотезы и старая тема не становятся фактами.
- Инструкция требует покрывать существенные части вопроса, сохранять связанные
  условия и числовые границы, перечислять только ещё неизвестные поля.
- Отсутствие технической документации больше не блокирует консультацию.
  Запрос самой документации или пошаговой настройки остаётся вне задачи.
- При явной просьбе перезвонить и уже указанном номере техническая анкета не
  задерживает передачу задачи. Если одновременно задан продуктовый вопрос,
  сохраняется ответ по существу. Реальная отправка заявки не заявляется.

Интерфейсы веба и CSV сохранены. `CLIENT_FACTS=1` и `ANSWER_COMPLETENESS=1`
включены по умолчанию, каждый можно отключить для сравнения. Дополнительного
вызова LLM эти правки не требуют. `ANSWER_REVIEW=0` остаётся по умолчанию.

## Что измерили

Заморожены 24 собственных сценария с пятью **вымышленными** документами:
6 пилотных, 10 для разработки, 8 отложенных. Закрытая база во внешний Groq
в этих опытах не отправлялась. Сырые запросы, ответы, события, токены и хеши
исходников остаются локально в `runtime/evaluation/groq/`, без ключей.

| Проверка | Контроль | Кандидат | Как читать |
| --- | --- | --- | --- |
| 10 сценариев разработки, инструкция полноты | 7/10 | 9/10 | Совпадение обязательных/запретных шаблонов, не оценка судьи |
| 3 выбранные ошибки диалога/контроллера | 2/3 | 3/3 | Повторное использование случаев разработки, не независимый тест |
| 8 отложенных, выбранная комбинация | 7/8 | 8/8 | Формальный прирост вызван формулировкой: контроль тоже правильно отказал при мощности ниже порога |
| Медиана времени генерации, отложенные | 2,17 с | 2,30 с | Исключены искусственные паузы по лимиту API |
| Суммарные токены, отложенные | 16 415 | 19 504 | Около +19%; 8 вызовов у каждой версии |

Ручная проверка важнее шаблонов. На разработке исправлены пропущенный второй
диапазон окупаемости, повторный вопрос об уже известном офисе и ложный отказ
из-за отсутствия документации. В одном случае полезный ответ о цене терялся
из-за отсутствия ID источника; инструкция помогла модели указать источник.

Отложенный набор **не доказывает улучшение качества в целом**: кандидат добавил
«встроенный модуль связи», которого нет в переданном материале. SIM-карты в нём
упомянуты, поэтому сами по себе не являются выдумкой. Кандидат также предложил
рассмотреть увеличение мощности без такого совета в источниках. Эти ошибки
не покрыты исходными регулярными выражениями.
Набор после просмотра результатов не менялся; новых правил по этим восьми
ответам не подбирали. Повторный прогон уже не будет независимой проверкой.

Четыре пары дополнительно рассмотрела та же модель вслепую, каждую в двух
порядках A/B (8 вызовов). Для обоих диапазонов окупаемости она дважды выбрала
кандидата; для порога мощности — дважды ничью. Для повторной анкеты выбор
поменялся с перестановкой ответов, причём судья во втором порядке проигнорировал
известный офис. Для способа связи были ничья и победа контроля: во втором
порядке судья обнаружил выдуманный встроенный модуль. Усреднять эти результаты
в оценку конкурсного score нельзя: это выбранные пары, тот же генератор и
заметная нестабильность с учётом истории и полноты проверки.

## Что не включили

- Проверка ответа второй модельной генерацией спасла один ответ без ссылки,
  но на пилоте не замечала пропущенную альтернативу или условие. Это полезная
  экспериментальная опция, а не доказанная защита достоверности.
- Короткая схема без полной карточки проверена лишь на двух случаях; были
  ошибки вспомогательных полей. Она не стала основной схемой.
- Локальный гибрид BM25 с символьным TF-IDF на 30 приватных метках дал
  25 → 26 случаев с любым целевым фрагментом и 23 → 24 со всеми, но потерял
  важный фрагмент числовых условий. Подмена поиска не принята. Добавление двух
  синонимов не дало прироста. Новых зависимостей нет.

Поиск остаётся BM25 с дополнением условий и обзоров. По текущей локальной
разметке он находит все целевые фрагменты в 23/30 случаев и хотя бы один в 25/30.
Это рабочая основа с пробелами. Следующий приоритет — достоверность конкретного
ответа и проверка на конкурсной Qwen, вместе с разбором оставшихся промахов
поиска. Переключение модели на Groq в конкурсном ZIP не зашито.

## Повторение

Для локального Groq настройте `.env` через `LLM_BASE_URL`, `LLM_API_KEY`,
`LLM_MODEL` (либо уже настроенные ссылки на `GROQ_*`). Не публикуйте ключ.

```sh
python3 evaluation/quality/groq_eval.py --label my-dev-run --split dev --variants baseline complete_state --max-calls 24 --pause 15
python3 -m unittest discover -s evaluation/backend -p 'test_*.py'
python3 -m unittest discover -s evaluation/rag -p 'test_*.py'
python3 -m unittest evaluation.quality.test_groq_eval
python3 scripts/build_submission.py
```

Имя запуска уникально; старые результаты не перезаписываются. Контроль
загружается из Git (`--baseline-ref c00f658`), а не из изменённого файла.
Повторное использование сырых контрольных ответов требует совпадения модели,
набора и точных сообщений. При 429 опыт останавливается; заголовки авторизации
и тело ошибки не сохраняются. Пауза 15 с рассчитана на текущий свободный лимит,
не гарантирует отсутствие 429 при параллельных запросах.

Проверены 80 backend-тестов, 49 RAG-тестов и 3 теста инструмента оценки.
Распакованный плоский ZIP локально прошёл 18 демо-ID в обоих режимах флагов:
без ошибок строк, без запасных ответов и с 18 вызовами явно синтетического
транспорта. Это проверка интеграции, не качества ответов на реальной базе.
Для оценки Qwen и расходования попытки нужен Платон; автоматической загрузки нет.
