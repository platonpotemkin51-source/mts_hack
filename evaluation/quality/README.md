# Локальное сравнение качества

Дата: 15.11.2026. Исходный архив `submission-fixed.zip` соответствует коммиту `2b921c1` и SHA-256 `68095a53cd005b84ed674da775e8bd42e6fd591806ce664e26c6eb39f13ec066`. Пользователь подтвердил его публичную оценку около 0,37; детальная разбивка платформы недоступна. Проверяемая база содержит 19 документов и 233 фрагмента. Локального доступа к настоящему Qwen3.8-27B нет.

Фиксированная до изменений разметка находится в игнорируемом `runtime/evaluation/quality-manifest.json`, SHA-256 `435440ca13bcf544988c332b66792359fa77e499cc1e2301583304533b92efd9`. В ней 6 случаев разработки (4 с размеченными фрагментами) и 7 отложенных случаев с размеченными фрагментами. Есть одношаговые вопросы, история, смена темы, неоднозначность, отказ от контакта, отсутствие цены в базе и существенные оговорки. Для каждого заранее указаны ожидаемые факты, запреты и требуемые разделы. Закрытые формулировки и фрагменты не публикуются.

Все 6 синтетических проб во всех вариантах сохранили **0 неподтверждённых продуктовых утверждений**: без проверенного источника утверждение заменяется безопасным ответом. Один общий отказ в B–D намеренный: модель указала неизвестный ID источника и заявила неподтверждённую возможность. Тесты специально включают вредоносное сочетание фразы «нет данных» с обещанием бесплатной функции. Показатели проб измеряют обработку заданных ответов, а не качество настоящей модели.

На демо №12 исходный поиск находил порог, но пропускал аудит существующего учёта; в C и D оба условия попали в контекст. На демо №15 исходный поиск видел общие разделы, а D добавил обзорные фрагменты двух релевантных решений без удаления найденных ограничений. На демо №18 исходный поиск не видел сведения для оценки учёта, потому что последняя реплика была про отказ от телефона; C и D восстановили цель и параметры из истории. Переключение темы проверено отдельно, старый объект не добавляется в новый запрос. Два пропуска в отложенной выборке остались; она не использовалась для подбора правил.

Время построения индекса на этом компьютере составило 55–75 мс. Поиск измерен на 13 фиксированных вопросах по 50 повторов для каждого этапа с уже построенным индексом. Измерение не включает генерацию и не гарантирует задержку на платформе. Embeddings и hybrid RRF уже реализованы и проходят тесты на искусственных векторах, но сравнение с настоящими моделями организаторов локально невозможно. Реранкер не включён. Слепое попарное сравнение реальных ответов с перестановкой порядка также невозможно без доступа к Qwen; публичную метрику из локальных чисел не прогнозируем.

Выбран D: дополнительный обзор появляется только если поиск уже нашёл два разных продукта не менее двух раз каждый; исходные шесть фрагментов, включая ограничения, сохраняются. Это дало один дополнительный полный контекст на выборке разработки при неизменной отложенной выборке. Прирост реального балла должна подтвердить следующая отправка, расходуемая только пользователем.

Проверки после изменений: 27 backend/CSV-тестов, 41 RAG-тест, 13 браузерных тестов, сборка интерфейса. Сквозной Docker-прогон прошёл через реальный nginx, FastAPI, SQLite и базу с **синтетическим** прокси, включая историю, карточку, отказ от контакта, заявку и архив. ZIP распакован в отдельный временный каталог с копиями входных файлов и запущен штатной командой `python solution.py`: 18/18 непустых уникальных строк и код 0 при 18 успешных тестовых ответах; при одном искусственном 401 — те же 18 строк, код 0 и счётчик одного аварийного ответа. Медленно передаваемый HTTP-ответ прерван до общего дедлайна.

Повторить локальные проверки из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s evaluation/backend -p 'test_*.py'
.\.venv\Scripts\python.exe -m unittest discover -s evaluation/rag -p 'test_*.py'
$env:PYTHONPATH=(Get-Location).Path
.\.venv\Scripts\python.exe runtime/evaluation/score_retrieval.py --project-root . --data-dir data --manifest runtime/evaluation/quality-manifest.json --output runtime/evaluation/D-retrieval.json --expanded
.\.venv\Scripts\python.exe runtime/evaluation/probe_generation.py --project-root . --output runtime/evaluation/D-generation.json
.\.venv\Scripts\python.exe scripts/build_submission.py
.\.venv\Scripts\python.exe runtime/evaluation/zip_smoke.py
```

`runtime/evaluation/` и исходная база игнорируются Git. Настройки для платформы: `RETRIEVAL_MODE=bm25` по умолчанию, `TOP_K=6`, `MAX_WORKERS=2`, `MAX_TOKENS=2048`; короткие ID фрагментов автоматически сопоставляются с настоящими. В stderr печатаются только агрегаты ошибок транспорта, HTTP, таймаутов, пустых и обрезанных ответов, ошибок JSON, неизвестных источников, общих отказов, аварийных подстановок, `finish_reason` и числовых `usage`. Тексты вопросов, документы, контакты и ключи туда не попадают.
