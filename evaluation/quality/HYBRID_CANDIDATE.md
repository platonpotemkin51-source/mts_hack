# Кандидат: BM25 + BAAI/bge-m3 с сохранением ограничений

Контроль — `cce72e1`; основной режим сравнения — фрагменты. Полные документы
и дополнительная проверка чисел не включаются в этот кандидат. Сообщённый
пользователем лучший результат — 59,278; оставшиеся попытки — четыре.
Архивы автоматически на платформу не отправлять.

## Что сверено с организаторами

Повторно прочитан раздел 6–7 технического регламента и локальный sample_submission.zip.
Адрес и служебный ключ локального прокси платформа передаёт сама. Для генерации,
эмбеддингов и реранжирования используется один прокси; BAAI/bge-m3 доступна на
платформе. Искать у участников отдельный внешний ключ не требуется.

Запрос из примера: POST /embeddings, JSON model и input, ответ data[index,embedding].
Имя берётся из EMB_MODEL, иначе baai/bge-m3; ключ — EMBEDDER_API_KEY или ключ LLM.
Реальный сервис локально недоступен. Искусственные векторы в проверках ниже —
только тест транспорта и интеграции, не работающая локальная модель эмбеддингов.

## Изменение

Существующий гибрид объединял первые 20 лексических и векторных результатов
по рангам RRF, но терял добор ограничений и требований к данным. Теперь
retrieve_with_evidence передаёт гибридную выдачу в общий механизм BM25-добора.
Кандидаты гибрида сохраняются в начале; добавляются связанные полные фрагменты
условий и исключений. Дополнительный embedding-запрос для добора не выполняется.
Контракт retrieve(top_k) и отсутствие скрытого fallback не меняются.

На холодном запуске индексируются 234 фрагмента: 15 пачек не более 16 текстов.
Далее один embedding-запрос на непустой поисковый запрос. Векторы кэшируются по
хешу базы, модели и прокси. Ошибки доступа/формата видны, а не маскируются BM25.

## Проверки

- 97 backend/CSV, 61 RAG и 3 теста инструмента оценки прошли.
- Новый сценарий: лексического совпадения нет, dense-канал даёт продукт;
  его ограничение всё равно доставляется в контекст.
- Проверено, что один поиск делает один semantic-вызов, без дублей embedding-запроса.
- Проверены порядок/дедупликация, кэш, размеры и нормализация векторов,
  HTTP-контракт и явная ошибка сервиса; прежние тесты сохранены.
- Распакованный ZIP обработал все 18 демо-ID в двух режимах флагов через явно
  синтетические HTTP-транспорты embeddings и генерации. По 18 вызовов генерации,
  без аварийных ответов. 51 embedding HTTP-вызов: 15 пачек индекса + 36 запросов.

## Сборка и ограничения

```sh
python3 scripts/build_submission.py --retrieval-mode hybrid
```

Внутри упакованного solution.py режим hybrid задаётся по умолчанию. Если платформа
явно передаёт RETRIEVAL_MODE, её значение имеет приоритет. CONTEXT_MODE остаётся
chunks, генеративная модель и доступ берутся из среды организаторов. Архив
сохранён отдельно: runtime/submission-hybrid-evidence.zip. Для контрольной сборки
используйте build_submission.py без параметров. Данные и ключи не входят в ZIP.

Улучшение retrieval на настоящей BAAI/bge-m3, скорость платформенного индексирования
и рост score локально не проверены. Поэтому этот файл описывает готовность
интеграции, а не доказанный прирост качества. С четырьмя попытками сначала изучить
доступную выгрузку прошлых ответов; резервные варианты не отправлять подряд.

## Проверка конечных ответов предыдущего эксперимента

Сравнили на Groq openai/gpt-oss-20b два реальных вопроса в режимах chunks/documents:
четыре генерации, temperature=0, MAX_TOKENS=1536, одинаковые остальные настройки.
Исходные вопросы, контексты и ответы остаются в runtime/evaluation/document-answers.json.

Ручная сверка с переданными материалами: в обоих случаях оба режима сохранили
основной правильный вывод. В первом полные документы дали дополнительное
подтверждённое пояснение, но не изменили ответ по существу. Во втором добавилось
обязательное действие, необходимость которого переданные материалы прямо не
подтверждают. Поэтому преимущества documents не установлено; случайная малая
выборка и другая модель не позволяют оценить официальный score.

Решение при четырёх оставшихся попытках: documents оставить резервным.
Гибрид — отдельная гипотеза для одного платформенного сравнения, а не обещанный
прирост. Не смешивать его одновременно с полными документами или новым промптом.
