# Эксперимент: полные продуктовые документы

Сравнение с новым архивом на платформе пока не выполнено.

`CONTEXT_MODE=documents` заменяет фрагменты максимум двух выбранных продуктов
полными исходными документами. Выбор опирается на поддержку продукта в основной
выдаче; остальные найденные справочные материалы сохраняются. Документ получает
собственный стабильный ID и участвует в обычной проверке источников. Таблицы,
ограничения и хвост документа не обрезаются. При превышении 40 000 символов
контекста конкретная замена пропускается, сохраняются прежние фрагменты.

По умолчанию остаётся `CONTEXT_MODE=chunks`. Протокол Retriever.retrieve и
HTTP-контракт не меняются. Полные исходники передаются BM25 при построении,
в том числе при использовании кэша фрагментов. Новых зависимостей нет.
Режим documents сейчас требует BM25; для embeddings/hybrid явная ошибка,
чтобы не выдавать обычный поиск за эксперимент с полными документами.

На 30 существующих приватных запросах без дополнительного восстановления
истории полное покрытие текстовых признаков в целевых документах: 26/30 → 27/30,
хотя бы одного: 27/30 → 28/30, регрессий на этом наборе нет. Медиана контекста:
5113 → 15916 символов; максимум кандидата — 33522 символа. Разметка не менялась.
Это старый набор разработки и оценка доступных фактов, не оценка ответа модели.
Числа не сопоставлять с проверкой после восстановления истории из другого отчёта.

Проверки: целый документ с удалённой оговоркой, сохранение посторонней справки,
уникальность и стабильность ID, отказ от обрезки большого документа, пустой поиск,
валидация top_k, доставка полного текста и проверяемого ID в общее ядро.

Сборка отдельного кандидата:

```sh
python3 scripts/build_submission.py --context-mode documents
```

Только в упакованном solution.py устанавливается значение documents по умолчанию;
переменная окружения CONTEXT_MODE=chunks позволяет вернуть контроль. Архив
сохранён как runtime/submission-document-context.zip. В нём нет базы или ключей.
Обычная сборка без флага сохраняет прежнее поведение.

Риск: больше шума и входных токенов, возможно увеличение задержки. Документы
выбираются лексическим поиском, поэтому неверный выбор продукта не устранён.
Внешняя генерация с полными документами и конкурсный score не проверены.
