# Селективная проверка ответа (отдельный режим)

`ANSWER_REVIEW=1` включает максимум один дополнительный вызов того же генератора
после разбора черновика. По умолчанию `0`: время и качество настоящей Qwen пока
не проверены. Новый сервис, модель и зависимости не нужны. Полезные изменения
диалога работают независимо от этого переключателя.

Поводы проверки: продуктовый ответ без действительных ID источников (не безопасное
уточнение и не простой переход к специалисту), новое число относительно переданного
контекста и пользовательских фактов, либо категоричная гарантия/универсальная
совместимость. Это сигналы риска, не доказательства ошибки. Число после пересчёта
единиц может быть корректным; код не запрещает его автоматически.

Проверяющий получает исходный вопрос, историю, все переданные фрагменты и черновик
в JSON. Ему поручено исправить неподтверждённое, сохранить условия и полезную часть
консультации, не переспрашивать известное и не давить после отказа от контактов.
Из ответа проверяющего применяются только текст и проверенные ID. Карточка клиента,
согласие, выжимка для менеджера и решение о предложении заявки не перезаписываются.

После проверки снова работает обычная проверка ID источников. Неизвестные ID не
открывают путь к продуктовым утверждениям. Если проверяющий недоступен, вернул
неразбираемый ответ или продуктовый ответ с несуществующими ID, сохраняется первый
результат, который затем проходит прежние проверки. В этом случае его нельзя
называть подтверждённым проверяющим. Повторной петли проверки нет.

Диагностика: `answer_review`, `answer_review_applied`, `answer_review_failed`,
`review_missing_sources`, `review_new_numbers`, `review_strong_promise`.
Время проверки включено в `generation_ms`; HTTP-клиент использует тот же общий
дедлайн конкурсного запуска. Число вызовов, задержка и риск тайм-аута увеличиваются.
Всё это нужно измерить на платформе отдельно от исправлений диалога.

10 синтетических тестов проверяют протокол ремонта, возвращение корректных
источников, отсутствие лишних вызовов для обычных ответов, выключение режима,
ошибки проверяющего, сохранность карточки и запрет обхода проверки ID.
Это не измерение семантического качества Qwen: два вызова одной модели могут
повторить одну ошибку. Сигналы не обнаруживают все противоречия (например, верное
число, ошибочно отнесённое к другому продукту).

Для локального A/B при доступном прокси: запустить один набор при `ANSWER_REVIEW=0`
и `1`, сохранив остальные настройки. Если на платформе нельзя задавать произвольные
переменные, для отдельного кандидата выбрать режим в адаптере до запуска:
`os.environ.setdefault("ANSWER_REVIEW", "1")`. Контрольную сборку оставить с `0`.
Сабмиты не отправлялись, закрытые материалы внешним провайдерам не передавались.
