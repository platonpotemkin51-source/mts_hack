# Правки конкурсного ответа и пропущенных доказательств

Контроль кода — `d3a71f2`. Лидерборд не проверен, сабмит не отправлен.
По решению пользователя реальные вопросы и база не передаются в Groq:
приватные проверки ниже выполнены локально; сетевые — только на вымышленных данных.

## Изменения

1. Конкурсная модель формирует ответ и ID источников, без веб-карточки на каждом
   вопросе. Системная инструкция сосредоточена на ситуации клиента и существенных
   условиях. Веб сохраняет полную схему. Проверка источников продолжает работать.
2. При прямом переходе к специалисту исходные реплики о задаче подхватываются
   даже при отсутствии модельного `manager_evidence`. Используются только
   проверяемые дословные сведения, без телефона и устаревших чисел.
3. Лексический поиск нормализует составные слова о тарифности. Второй канал по
   символьным 3–4-граммам добирает максимум два целых фрагмента в пределах 1800
   символов, сохраняя основную выдачу и ограничиваясь уже выбранными продуктами.
   Он не включает ответ на запрос без лексических совпадений. Исключающие условия
   добираются отдельно от описания идеального клиента.
4. Исправлена обработка экспортного артефакта: экранированный заголовок,
   приклеенный к предыдущему предложению, снова отделяет требования к данным.
   Кодовые блоки сохраняются. Обновлены версии нарезки и индекса для сброса кэша.
5. Справочный раздел связывается с продуктом при выборе дополнительных условий.
   Короткая справка не заменяет подробные требования в самом продуктовом документе.
   Корневой вводный раздел учитывается и без отдельного заголовка «Что это».

## Локальная проверка на базе

Заморожены оба старых модуля — `retrieval.py` и `chunking.py` из `d3a71f2`.
Одинаковые вопросы и восстановление контекста, 30 имеющихся случаев. Вопросы,
фрагменты и детализация остаются в игнорируемом `runtime/evaluation/`.

| Проверка | Контроль | Кандидат |
| --- | ---: | ---: |
| Все обязательные текстовые признаки из существующей разметки найдены в нужных документах | 24/30 | 28/30 |
| Все целевые разделы по прежнему заголовку и текстовым признакам | 23/30 | 25/30 |
| Хотя бы один целевой раздел | 25/30 | 28/30 |
| Медиана символов контекста | 4042 | 4755 |
| Фрагментов в индексе | 233 | 234 |

Вторая строка намеренно сохраняет старую привязку требований к названию раздела
до исправления нарезки. Первая проверяет исходные текстовые признаки и документ,
без требования старого заголовка. Формулировки и ожидаемые признаки не менялись.
Ни один случай не потерял совпавшие признаки; четыре получили недостающее.
Это оценка доступных модели доказательств, а не оценка её конечного ответа.

## Генерация и границы результата

На пяти вымышленных сценариях через Groq сравнили прежнюю и короткую схемы.
Выходные токены: 3194 → 1599; общие токены: 10 948 → 7969. Проверки обязательных
шаблонов: 5/5 → 4/5. Регрессия — потеря резюме при просьбе перезвонить — исправлена
дословным подхватом клиентской задачи. Повторная реальная генерация Groq сохранила
потребность и число приборов в конечном ответе; есть отдельный модульный тест
случая, когда модель забывает резюме и решение о заявке.

Для одного повторного контроля изменился состав контекста: инструмент отказался
переиспользовать несовпадающий запрос. Поэтому повторный прогон не объявляется
полным парным сравнением. В другом ответе Groq по-прежнему добавляет примеры
неизвестных полей вопреки инструкции; это остаётся недостатком генерации.
Официальный score из этих результатов не выводится.

Проверены 84 backend/CSV-теста, 54 RAG-теста и 3 теста инструмента оценки.
Распакованный плоский ZIP обработал 18 демо-ID без аварийных ответов в двух
режимах флагов через явно синтетический транспорт. Генераций — 18 на прогон,
дополнительный модельный проход по умолчанию выключен.

Сборка: `python3 scripts/build_submission.py`. Архив кандидата отдельно сохранён
как `runtime/submission-score-sprint.zip`. Для проверки генерации только на
вымышленных данных: `python3 evaluation/quality/groq_eval.py --label unique-name
--split dev --variants baseline candidate --baseline-ref d3a71f2 --max-calls 24`.
Следующий внешний шаг — сравнение на Qwen и конкурсный прогон у Платона.
