# Energytool — интерфейс Даниила

Vue 3 + TypeScript + Vite. Чат, серверная карточка клиента, заявки с согласием,
архив только для чтения, источники и времена. Общие типы и исходный mock сохранены.

## Запуск

Node.js 22+ и npm. Из корня проекта:

```powershell
cd frontend
npm ci
npm run dev
```

Открыть http://localhost:5173. По умолчанию используется настоящий API;
Vite проксирует `/api` на `http://localhost:8000`.
В исходном backend-каркасе есть только health: чат без интеграции покажет ошибку.

Явная демонстрация без backend (PowerShell):

```powershell
$env:VITE_USE_MOCK_API="true"
npm run dev
```

Для реального сценария установить `VITE_USE_MOCK_API=false` и перезапустить Vite.
Можно скопировать `.env.example` в `.env.local`. Переменные применяются
при старте dev-сервера / сборке, а не при запуске уже собранной статики.
`VITE_API_BASE_URL` — origin API без суффикса `/api`; пустое значение означает
тот же origin. При отдельном origin backend должен разрешить CORS.
Никакие ключи LLM в frontend не передаются.

Mock использует `mocks/chat-response.json`, затем фиксированный синтетический ответ.
Он не анализирует текст и не рекомендует продукты. Карточка склада фиксирована,
источники пустые, времена нулевые. Баннер явно предупреждает об этом.
Демо-архив сохраняется только в sessionStorage данной вкладки, без активного ID;
это не замена серверного хранения. Контакты используйте вымышленные.

## Сборка и проверки

```powershell
npm run build
npm run preview
npm test
```

Сборка в `frontend/dist`, preview на 4173. Нужен современный браузер с ES2022.
Тесты Playwright используют установленный Microsoft Edge,
поднимают Vite и подменяют HTTP-ответы синтетическими fixtures.
Тестовые порты должны быть свободны. На Linux можно установить Chromium
через `npx playwright install chromium` и убрать `channel: 'msedge'` из конфигурации.
Отчёт: `evaluation/ui/README.md`, сценарий: `docs/DEMO.md`.

## Передача Платону

Подключены `POST /api/chat`, `POST /api/leads`, `GET /api/sessions`,
`GET /api/sessions/{id}`, `POST /api/sessions/{id}/close`.
Отдельное создание сессии не нужно: первое сообщение передаёт `session_id: null`.
Карточка берётся целиком из `brief`, резюме заявки — из `LeadResponse.summary`.

Новый диалог, закрытие чата и pagehide сбрасывают локальное состояние и пытаются
закрыть сессию. Незавершённый ответ игнорируется по поколению диалога;
если первый ответ приходит позже, его серверный ID также закрывается.
Закрытие страницы до получения первого ID невозможно гарантированно закрыть
на клиенте — нужна серверная политика для потерянных запросов/сессий.

После ошибки чата отправка блокируется до нового диалога, история остаётся,
предлагается проверить архив. Автоповторов нет: контракт не содержит idempotency key
или подтверждения сохранения сообщения. Требуется согласовать безопасный повтор
с backend; общие поля не менялись. Заявка защищена локальным busy-флагом и серверным
409 при дубликате. После ошибки заявки следует проверить архив перед повтором.

Docker-контекст — `frontend/`, внутренний порт 80. `nginx.conf` ожидает сервис
`backend:8000`, проксирует `/api` без изменения пути. Для Compose Платону нужно
добавить этот сервис, зависимость от backend и опубликованный порт, например 5173:80.
Docker-сборка не включает `.env*` и по умолчанию выключает mock.
Compose и общие файлы не менялись. Docker требует отдельного интеграционного прогона.

Ответы отображаются как Vue-текст, без `v-html`; ошибки имеют локальные
формулировки вместо сырых исключений сервера. Отладка выводит только
оговорённые поля источников/времён, абсолютные пути в `source` скрыты.
Backend обязан не включать секреты и внутренние промпты в поля ответа/фрагментов.
